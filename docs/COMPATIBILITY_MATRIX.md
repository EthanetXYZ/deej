# Compatibility matrix

For every original behaviour, this lists what deej Next does and how that will be verified.

**Plan column:**

- **Keep:** identical behaviour.
- **Superset:** everything that worked still works the same, and some inputs that previously failed now work.
- **Change:** an intentional difference that needs your approval.
- **New:** an addition with no original counterpart, opt-in or invisible to legacy configs.

**Test column:**

- **U:** automated unit test.
- **G:** golden test against values generated by the Go implementation.
- **I:** Windows integration test that needs a real audio device.
- **H:** manual test on real Arduino hardware.
- **M:** manual UI test.

Owner decisions (2026-10-12): every "needs your approval" item below was approved as proposed. S18 (multiple boards) is deferred until after v1.

**Implemented and tested in Phase 1:** C1, C2, C3, C4 (startup), C7–C12, C13, C14–C21 (loading), C25 and C26 (parsing), and C27. Each is covered by unit tests, and by `tests/golden_config.rs` against output from the real Go libraries.

**Implemented in Phase 2 (audio engine, `crates/deej-audio`):**
- **Tested on real devices** (`tests/windows_engine.rs`): A1 (default render device, console role), A3 (system sessions on every device), A4/A5 (sessions per exe on all playback devices; device friendly names), A12 (skip if unchanged), A13 (same event-context GUID, external changes flagged), A14 (discovery part: new sessions arrive by notification), A16 (expired or exited sessions dropped).
- **Engine support done, end-to-end test later:** A2 (`mic`: the default capture device is resolved, but its level isn't changed in the tests so your mic isn't disturbed), A15 (default-device change: handled, needs a manual check), A18 (mute: endpoint mute tested, UI in Phase 5).
- **Not tested yet:** A20 (no audio device / RDP).

Target resolution (the `slider_mapping` semantics) is Phase 4.

**Implemented in Phase 3 (`deej-core::protocol` and `crates/deej-serial`):**
- **Golden-tested bit-for-bit against the Go code:** S1, S2, S3 (including the fork-bug fix), S4, S5, S6, S7, S8, S17.
- **Tested with a fake board:** S13, S14, S15, S16, S12 (one-way by construction: the port type has no write method), S19 (no limit).
- **Tested on the real board (Arduino Uno R3, COM3):** S9, S10 and S11 (DTR on resets the Uno, as with Go; DTR off doesn't; RTS has no effect on it), connecting, slider detection and readings.

**Implemented in Phase 4 (mapping, coordinator, config writer):**
- **Unit-tested:**
  - Mapping: A4, A6, A7, A9 and A10 (`deej-core::mapping`).
  - Coordinator, with a fake board and fake audio: A11, A14, A15, A17, S16, S17, C5 and C6.
  - Writer and store: C21, C22, C23 and C24, with every fixture config edited and checked semantically.
- **Golden-tested:** A11 (the sensitivity curve), bit-exact against Go on 5,148 cases.
- **End-to-end on the owner's machine** (real board, real config, real apps):
  - `deej.unmapped` with `unmapped_exclude`, groups, and curves on real sessions.
  - Live config reload, a broken file keeping the previous settings, and recovery.
  - Graceful shutdown.
- **A8 changed as planned:** the `deej.unmapped` set is computed from the current sessions every time.

**Implemented in Phase 5 (user interface):**
- W16: every setting from the fork's settings window: sensitivity per slider and default, port, invert, noise, exclusions and live positions.
- W17: the mapping editor.
- A18: superseded by D22. The owner dropped the UI mixer and its mute buttons; master mute stays planned for the tray menu. Sliders never change mute state.

These were checked against the mock backend in the browser pane (dark and light themes, every page, and the commands each interaction sends) and with a real-data render report from the real window on the owner's PC.

**Implemented in Phase 6 (Windows integration):**
- W1: tray menu with status, Open deej, Mute playback, Playback device ▸ (switches the default device through `IPolicyConfig`, R7), Restart board connection, Re-scan audio, Edit config.yaml, Start with Windows, version, Quit deej.
- W2: left-click opens the window. W5: Edit config.yaml opens Notepad.
- W3: removed by the owner (D27, 2026-10-13). The tooltip is just "deej".
- W4: one notification per board outage (after 5 s) and its end; config errors and reloads while the window is closed. Routine ones can be turned off (D26).
- W6: `DEEJ_NO_TRAY_ICON` runs without a tray icon; closing the window then quits, since nothing else could reopen it.
- W8: `--settings` is accepted; the window opens on a normal start anyway. `--minimized` starts in the tray (used by autostart).
- W10: changed per D23: the Run value is `deej-next`, and only entries that start this exe are counted or removed. Other deej entries are shown as a warning, never removed.
- W11: a second launch hands over to the running copy, which opens its window.
- W12: closing the window keeps deej running in the tray and destroys the WebView (D24). A one-time notification says where it went.
- W13: on resume from sleep, the board is reconnected and audio re-scanned after 3 s.

Checked on the owner's PC with the release build: start in the tray with no window (31 MB), second launch → window, close → still running, position restored, the Go deej's Startup shortcut detected through `IShellLink`. **Not yet checked by a person:** the tray menu items, switching the playback device, sleep/resume, an Explorer restart, a reboot with autostart (see DEVELOPMENT_STATUS.md).

Every row not listed above: not started.

## 1. Serial protocol and hardware

| S3 | Value > 1023 in any field | first field only rejected | whole line rejected | **Keep (fork)**: reject the whole line, **without** the fork's partial-state bug | U |
| S4 | Garbage, partial or empty lines | silently dropped | same | **Keep**; also counted in diagnostics | U |
| S5 | Slider count inferred from each line; a change re-sends all | ✓ | ✓ | **Keep** | U |

| S7 | Invert `1 − p` in f32 | ✓ | ✓ | **Keep**, bit-exact | G |
| S8 | Noise thresholds 0.015/0.025/0.035, snap to 0/1, case-sensitive level | ✓ | ✓ | **Keep** | G (all transition pairs × 3 levels) |
| S9 | 8N1, no flow control, configured baud | ✓ | ✓ | **Keep** | U (settings struct), H |
| S10 | DTR asserted on open | ✓ | ✓ | **Keep** (default `dtr: true`) | H (Nano, Pro Micro if available) |
| S11 | RTS on open | off | on | **Keep upstream** (off) by default, configurable via `deej_next.serial.rts` | H |
| S12 | One-way protocol, no writes to the board | ✓ | ✓ | **Keep**; never write unless a future opt-in feature needs it | U (mock port asserts no writes) |
| S13 | Unbounded line buffer | ✓ | ✓ | **Change**: cap at 4 KiB and discard until the next newline (no effect on valid streams) | U |
| S14 | Port missing or busy at start | quit | retry 2 s + one toast | **Keep (fork)** | U (mock), H |
